# Changelog

## v8.0.0 (August 21, 2026)

**BREAKING CHANGE:** State-changing account routes now require a CSRF token. Affected endpoints: `Address-DeleteAddress`, `Address-SetDefault`, and `PaymentInstruments-DeletePayment`. Storefronts or cartridges that call these routes without a valid CSRF token must be updated.

**BREAKING CHANGE:** `Address-DeleteAddress`, `Address-SetDefault`, and `PaymentInstruments-DeletePayment` are now `POST` routes. Callers issuing these requests over `GET` must switch to `POST` and send the CSRF token in the request body instead of the query string.

- Security: Require a CSRF token on the state-changing account address and saved-payment routes.
- Security: Reclassify the state-changing account address and saved-payment routes from `GET` to `POST` so the CSRF token no longer travels on the query string.
- Removed the deprecated `ConsentTracking-SetSession` endpoint, which was superseded by the CSRF-protected `ConsentTracking-SetConsent`.
- Render resolved page meta tags on Page Designer custom pages [#1484](https://github.com/SalesforceCommerceCloud/storefront-reference-architecture/pull/1484)
- Support component rendering in isolation [#1478](https://github.com/SalesforceCommerceCloud/storefront-reference-architecture/pull/1478)
-   Renamed the Page Designer carousels' `data-keyboard`/`data-interval` to `data-bs-keyboard`/`data-bs-interval` on the carousel root in `commerce_layouts/carousel.isml` and `einstein/einsteinCarousel.isml`, matching the earlier `imageCarousel.isml` fix. The `data-slide` control links were already renamed to `data-bs-slide`, but the root's config attributes were left unprefixed; Bootstrap 5 ignores unprefixed config, so `data-interval="false"` was inert and a merchandiser-configured no-autoplay carousel picked up the default 5-second auto-cycle and advanced on its own. Because the markup is content-driven, the fix has to live in the cartridge.
-   Fixed two Bootstrap 5 regressions on the product detail page and on outline buttons site-wide. Renamed the PDP image carousel's `data-interval="0"` to `data-bs-interval="0"` in `imageCarousel.isml`: Bootstrap 5 ignores the unprefixed attribute, so the carousel picked up the default 5-second auto-cycle and advanced on its own instead of staying put for manual navigation. Pinned the `--bs-btn-hover-*` custom properties on `.btn-outline-primary` in `skin/skin.scss` back to the resting outline appearance (transparent fill, brand-blue text and border): Bootstrap 5's `.btn:focus-visible` repaints from the hover variables, which for an outline button default to a solid blue fill with black `color-contrast()` text, so keyboard-focusing any outline-primary button (address forms, checkout, cart and delete-payment modals) lost the outline look entirely. The explicit `:hover` rule still overrides these variables, so pointer hover keeps its intentional filled swap. Removed the `data-bs-toggle="modal" data-bs-target="#chooseBonusProductModal"` from both bonus-product buttons (`addToCartProduct.isml` and `cartEmbeddedBonusProducts.isml`): the bonus modal is built and shown entirely in JavaScript (`product/base.js` `chooseBonusProducts()`, reached on the PDP after the add-to-cart response and from the cart via `editBonusProducts()`), so `#chooseBonusProductModal` is never in the DOM when either button is clicked. Under Bootstrap 4 the jQuery plugin silently no-oped the missing target, but Bootstrap 5's vanilla Modal data-API resolves the target to `null` and constructs `Modal.getOrCreateInstance(null)`: the `Modal` subclass constructor runs past `BaseComponent`'s early return and reads `this._config.backdrop` on a config that was never set, throwing `Cannot read properties of undefined (reading 'backdrop')` on every click. The modal still opened (a separate jQuery click handler drives it), but each click logged the error; removing the vestigial attributes clears it.
-   Added merchant-facing Bootstrap 5 migration guidance: a `bootstrap-5-migration.md` guide at the repository root (linked from the README) documenting the mechanical data-attribute, utility-class, and form-class renames plus the manual jQuery-to-vanilla component conversions a Bootstrap 4 → 5 upgrade needs, and a `skills/bootstrap-5-migration` skill that walks a merchant through the renames, the manual JavaScript component conversions, and the verification checklist. No cartridge runtime changes.
-   Fixed the remaining Bootstrap 5 accessibility and functional regressions in the SFRA Base product quick view and image carousel. Dropped `aria-hidden="true"` from the `.carousel-indicators` container in both the server-rendered `imageCarousel.isml` and the `createCarousel()` rebuild in `product/base.js`: the container holds the focusable slide-to `<button>` controls, so marking it hidden while the buttons stayed tabbable was the direct cause of the "Blocked aria-hidden on an element because its descendant retained focus" warning when tabbing through the carousel. Blurred the focused control before Bootstrap hides the quick view modal (`product/quickView.js`) so the same warning stops firing on close, matching the pattern used for the other base modals. Reserved the scrollbar gutter on the quick view `.modal-body` and gave the rebuilt carousel a square box (`_quickView.scss`) so a variation-change AJAX swap no longer toggles the body scrollbar, shifts the image column width, and resizes the modal, and a freshly swapped image can't snap the carousel height on decode.
-   Fixed the accessibility and functional regressions the Bootstrap 5 upgrade introduced in the SFRA Base cartridge header and modals. Removed the `data-bs-toggle="dropdown"` attributes from the category mega-menu, country selector, and mobile account dropdown so Bootstrap 5's Dropdown data-API stops fighting the custom jQuery hover/keyboard code that positions and toggles those menus (the category dropdown no longer opened by mouse or keyboard). Added Enter and Space handlers to the top-level category keyboard navigation so a keyboard user can open a submenu, with the handler following the link natively on a leaf category. Deleted the manual and baked `aria-hidden` on the consent-tracking modal, the bonus-product modal, the edit-cart modal, the category and account dropdown-menu subtrees, and the desktop account popover — Bootstrap 5's Modal manages background inertness itself and open/closed state is carried on the toggle's `aria-expanded`, so the `aria-hidden` was both redundant and the direct cause of the "Blocked aria-hidden on an element because its descendant retained focus" console warning (the popover and menus receive keyboard focus while their subtree was marked hidden). Removed the consent modal's manual Tab focus-trap now that Bootstrap 5's Modal traps focus within the dialog, while keeping the on-open focus of the affirm button. Stopped bundling Bootstrap 5's Dropdown component: the `thirdParty/bootstrap-v5.js` shim now imports the eleven components this cartridge actually uses instead of the whole `bootstrap` barrel. Importing Dropdown registers a document-level keydown listener delegated to `.dropdown-menu` that resolves its owning toggle exclusively through the `data-bs-toggle="dropdown"` attribute these menus no longer carry, so keyboard navigation of the category mega-menu, country selector, and mobile account dropdown built a Dropdown around a null element and threw `Cannot read properties of undefined (reading 'parentNode')`. That listener registers in the capture phase, so it runs before any handler bound to the menu links and cannot be suppressed from within the menu — leaving the module out of the bundle is what keeps it off the document. Dropdown was only ever a side effect of the barrel import; no template or client script references it.
-   Restored the SFRA Base cartridge styling that regressed under Bootstrap 5. Rewrote every `media-breakpoint-down(xs)` callsite (24 across `_productCommon`, `cart`, `_miniCart`, `_headerSearch`, `_footer`, `search`, `homePage`, `checkout`, `detail`, `_productTiles`, `imageAndTextCommon`, `_extraSmallCarousel`) as `media-breakpoint-down(sm)` — Bootstrap 5 flipped the mixin's meaning from "breakpoint and narrower" to "below breakpoint" and returns a null max for `xs`, which had collapsed the guarded blocks and leaked mobile-only styling (white box + shadow around price/add-to-cart on PDP and around the checkout button in cart) into every viewport. Repaired the sibling `_responsiveUtils.scss` `.hidden-*-down` compat shim the same way so it maps back to the legacy behaviour, restoring the header search bar on `≥sm`. Renamed the header-banner, no-menu-header, and campaign-banner dismiss buttons to `btn-close btn-close-white` (three sites #1474 missed) and dropped their leftover `&times;` spans plus the `_header.scss` `color: $white` override that no longer applies to the SVG-mask `.btn-close`; the campaign-banner variant keeps its custom `close-icon.svg` under a dedicated `campaign-banner-close` selector so the icon renders once instead of stacking with `.btn-close`'s default `×`. Updated the paired click handlers (`components/menu.js` → `.header-banner .btn-close`, `campaignBanner.js` → `.campaign-banner .campaign-banner-close`), the WDIO page-object selector in `test/acceptance/pages/pageDesigner.page.js`, and the `skin/skin.scss` reskin override so all three dismiss buttons still bind, hide the banner, and pick up the skin colour. Added a `text-decoration: none` reset on the header `.user > a` so the guest Login link and the authenticated MyAccount link stop picking up BS5 Reboot's default underline. Justified the cart promo-code row with `align-items-start` + `g-2` so the input and submit button share a baseline, and paired-renamed the promo-code `<label>` to `form-label` in the same edit.
-   Replaced the removed jQuery Bootstrap component API calls (`$(...).modal('show'|'hide')`, `$(...).carousel('dispose'|'next'|'prev'|<init>)`) with the Bootstrap 5 vanilla JS API (`bootstrap.Modal.getOrCreateInstance(...)`, `bootstrap.Carousel.getOrCreateInstance(...)`) across `product/quickView.js`, `product/base.js`, `cart/cart.js`, `components/consentTracking.js`, and `carousel.js`. General jQuery usage (DOM, events, AJAX, spinner) is unchanged.
-   Bootstrap 4 → 5 structural form and layout conversions across the SFRA Base cartridge: `form-group` → `mb-3` utility spacing (with the `required` marker driving asterisk rendering via a descendant selector), `custom-control`/`custom-checkbox`/`custom-radio` families → `form-check` with `form-check-input`/`form-check-label` children, `custom-select` → `form-select` (dropping the co-occurring `form-control` on `<select>`), `btn-block` → each button wrapped in a `<div class="d-grid">` (drop the class), `input-group-append` wrapper removed, and the paired `form-control-label` → `form-label` rename. `_bootstrapOverrides.scss` rewritten with attribute selectors so checkbox and radio keep their distinct color gradients under the shared `form-check` structure; the `_formFields.scss` `form-group` shim is removed. Coupled client-side JS selectors (`clientSideValidation.js`, dynamic HTML in `login.js`) and E2E page-object selectors updated to match.
-   Bootstrap 4 → 5 mechanical class and attribute conversions across the SFRA Base cartridge: `data-*` attributes prefixed as `data-bs-*` (`data-toggle`, `data-dismiss`, `data-target`, `data-slide`, `data-slide-to`), `text-left`/`text-right` → `text-start`/`text-end` (including responsive variants), `float-left`/`float-right` and legacy `pull-left`/`pull-right` → `float-start`/`float-end`, `sr-only` → `visually-hidden`, `no-gutters` → `g-0`, and dismiss-button `class="close"` → `class="btn-close"`. Covers all locale template variants and coupled client-side JS selectors and inline HTML strings; E2E page-object selectors updated to match.
